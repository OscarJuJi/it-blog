## [Research Finds On-Policy LLM Distillation Works Better Without Teacher Models](https://dev.to/reidmarlow/on-policy-distillation-works-better-without-the-teacher-1ac1)

Purdue researchers Yi Ding and Ruqi Zhang analyzed on-policy distillation recipes for training small reasoning models and discovered that teacher model supervision consists primarily of noise. In standard setups, a larger teacher model assigns token-level advantage scores to sequences generated by the student, but because these sequences are off-policy for the teacher, evaluation error rates remain high regardless of teacher scale. Removing the teacher entirely and applying a simple negative penalty to low-probability tokens achieved performance that equaled or surpassed traditional teacher-guided distillation. For software engineers building or fine-tuning domain-specific reasoning models, this challenges the assumption that larger, costly teacher models are necessary for effective token-level reinforcement learning. In practice, teams can significantly reduce training compute costs and pipeline complexity by replacing teacher scoring infrastructure with lightweight policy penalization rules.

## [Analyzing the Design and Runtime Architecture of Claude Code Workflows](https://dev.to/hesreallyhim/claude-code-workflows-critical-analysis-34dn)

A technical breakdown of Claude Code dynamic workflows reveals how multi-agent orchestration is shifting from model prompts directly into application execution harnesses. Workflows run a custom JavaScript dialect inside a resumable runtime where top-level async calls are valid, but non-deterministic functions like system clocks are restricted to ensure execution state can be preserved. The runtime provides structured primitives including agent task execution, parallel fan-outs, sequential pipelines, and nested sub-workflows. Developers constructing complex agentic automation need to understand these boundary lines, as managing workflow state in code rather than relying on prompt-driven model decisions provides deterministic control over long-running jobs. In practice, engineers should structure complex developer tooling around explicit harness primitives rather than relying on continuous LLM re-prompting to manage multi-step execution graphs.

DoorDash has migrated its internal AI engineering agent workloads off local developer laptops onto a centralized cloud platform named Flux. The infrastructure processed over 130,000 engineering tasks in a single month and currently executes more than 25,000 automated code reviews per week. Flux executes agent tasks inside isolated Firecracker microVMs connected to a Model Context Protocol gateway, providing centralized audit logging, scoped access controls, and reusable task playbooks. As organizations scale AI assistant usage across engineering teams, running agents locally creates governance risks and resource constraints on developer workstations. In practice, infrastructure teams should build or adopt isolated containerized cloud environments with centralized protocol gateways to securely scale autonomous code generation and automated pull request reviews across production repositories.

## [Replacing Static Service Account Keys in GCP Using Workload Identity Federation](https://www.infoq.com/articles/gcp-wif-scale/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=global)

An engineering architecture post details the implementation of Google Cloud Platform Workload Identity Federation across more than 120 production projects to eliminate long-lived service account keys. Traditional service account keys act as static secrets that require complex secret rotation schedules and carry high leakage risks across deployment environments. Workload Identity Federation converts machine authentication into a single managed trust relationship, granting short-lived access tokens based on specific identity attributes and environmental conditions. Software and DevOps engineers managing cloud credentials gain a scalable pattern for securing machine-to-machine integrations without storing raw key files in continuous integration pipelines or key vaults. In practice, platform engineers should migrate workload authentication away from static credential files toward token exchange federations configured at the cloud provider boundary.

## [Keenable SELECT Exposes Web Search Agent Capabilities Through SQL Interfaces](https://keenableai.github.io/select-showcase/)

Keenable released Keenable SELECT, an open-source Model Context Protocol tool that enables AI agents to execute web research directly through SQL queries backed by DuckDB. The engine parses custom semantic functions like text extraction and semantic matching alongside standard relational clauses, executing deterministic SQL filters prior to invoking expensive language model evaluations. By filtering web search inputs at the database query level, the system minimizes token consumption compared to traditional approaches where agents consume raw web pages directly. Software developers building data-gathering agents or search integrations gain a structured alternative to standard unstructured retrieval-augmented generation pipelines. In practice, teams can optimize agent workflows by wrapping web scraping and filtering operations inside relational query engines rather than passing raw text payloads to LLM context windows.
